# 商城需求

更新日期：2026-10-16｜需求整理稿

预览：[移动端商城](https://yaloka-store-prototype.wintryvenus4.chatgpt.site/) · [后台商城列表](https://yaloka-store-prototype.wintryvenus4.chatgpt.site/admin.html#products) · [后台购买记录](https://yaloka-store-prototype.wintryvenus4.chatgpt.site/admin.html#orders)

商城关联现有特效，按「金币单价／天 × 购买天数」售卖。名称、缩略图、多语言及预览资源复用现有特效配置；充值、我的装扮复用线上功能。商品由运营手动配置并上架，本期不包含贵族、角色等级等专属特效，不新增专属资源自动识别或排除逻辑。

本稿以用户提供的 2026-10-15 需求为基础，仅将分类改为动态展示、创建改为支持批量新增，并补齐两项对应交互；此前固定总价、固定时长、排序自增、排序值越小越靠前、多语言缩略图分列等旧规则不再沿用。

## 一、移动端

### 1. 商城页面

- 标题 Store；Mine 跳转线上我的装扮，不新增装扮管理功能。
- **商城入口：**在 My 页面文字入口区域新增「Store」入口，点击后进入商城页面。
- 分类根据后台已上架且可售的商品类型动态展示，无可售商品的分类隐藏，不固定显示空分类。分类刷新复用现有缓存机制，不要求实时同步。
- 有商品的分类按以下相对顺序排列：Avatar Frame、Chat Bubble、Entry Bubble、Entry Ribbon、Ride、Badge、Shiny Name、Gift Banner、Profile Frame、Mic Aura、Colorful Text。本期客户端范围按这 11 类，不因后台类型枚举包含动态头像而新增客户端分类。
- 分类栏支持横向手势滑动，不显示滚动条。全部分类无商品时，居中显示 No data，Purchase 置灰，保留充值入口。
- 当前分类因缓存更新被移除时，切换到第一个可用分类，清除失效商品选择，其余分类的有效选择保留；若已无分类，则进入空状态。
- 商品根据后台配置的分类及排序展示，排序值越大越靠前；排序值相同时保持稳定顺序。
- 卡片展示缩略图、名称、金币单价／天及右上角播放按钮。界面文案使用英文，商品信息按用户语言读取现有特效配置。

### 2. 选择与预览

- 点击卡片右上角按钮仅预览，不改变商品选中状态；点击商品卡片其他区域，选中该商品并直接打开对应购买抽屉。每个分类只保留一个选中商品；重复点击当前商品也会重新打开购买抽屉。
- 首次进入默认第一个可用分类，不选中商品；底部金币余额及 Purchase 栏始终显示，未选中商品时 Purchase 置灰。
- 关闭购买抽屉后，保留当前商品选中状态，底部栏继续显示。点击当前选中商品或底部 Purchase，均打开该商品的购买抽屉；点击其他商品则选中该商品并直接打开对应抽屉。
- 切换分类保留各分类本次浏览中的商品选中状态；底部栏不因切换分类而隐藏。切换到有历史选中商品的分类时，Purchase 对应该分类历史选中商品；切换到没有选中商品的分类时，Purchase 置灰。
- 从购买抽屉、充值或我的装扮返回，保留分类及有效选中状态；退出商城重进重置。
- 预览在当前页蒙层播放一次，结束自动关闭；点击空白可提前关闭，不设关闭按钮。预览不改变选中状态。
- 预览失败 Toast：Preview failed. Please try again.

### 3. 购买抽屉

- 展示商品静态图、名称、时长选项及对应价格、金币余额、Purchase；各档价格＝金币单价／天 × 对应天数。
- 只显示后台勾选时长，按 3、7、15、30 天升序排列，默认第一档；每个时长选项直接展示对应价格，不再单独展示 Total 总计金额。
- 不播放特效，不设预览、取消或关闭按钮；非提交状态点击外部蒙层关闭。再次打开默认第一档，从充值返回保留原档位。
- 商城及抽屉的余额入口统一为「金币图标＋余额＋右箭头」，整块可点击拉起线上充值弹窗。

### 4. 购买与充值

- **余额不足：**Toast：Not enough coins. Top up first.，拉起线上充值弹窗
- **充值返回：**刷新余额，保留商品、时长，不自动购买；充值弹窗无额外关闭／取消按钮，点击蒙层收起
- **提交中：**禁止重复提交及切换本次商品、时长；不得通过关闭抽屉改变本次提交
- **商品下架或删除：**提交时提示不可售，刷新列表并清除失效选择
- **配置变化：**复用礼物面板缓存及刷新机制，不要求实时同步，缓存更新后展示最新配置；提交时仍由服务端校验可售状态及允许时长
- **购买失败：**提示原因，恢复按钮并保留有效选择；超时先核实原交易结果，避免重复购买
- **购买成功：**刷新余额及权益，关闭抽屉，展示成功弹窗

成功弹窗标题为 Purchase successful!，展示本次购买商品静态缩略图，复用已有商品数据，不显示打钩符号；两个等宽按钮为 Cancel、Go equip。Cancel 或点击外部空白关闭并留在商城；Go equip 跳转我的装扮对应分类，由用户佩戴。购买不自动佩戴。

## 二、运营后台

### 1. 菜单和商城列表

新增一级菜单「商城管理」，下设二级菜单「商城列表」「购买记录」。商城配置关联现有特效列表，不重复上传资源，不展示商品 ID。

筛选字段与组件同一行展示，支持组合查询和重置：

- **特效 ID：**输入查询
- **特效类型：**复用线上类型下拉，默认全部
- **状态：**全部／上架／下架，默认全部

列表字段按以下顺序展示：

- **特效 ID：**关联的现有特效 ID
- **特效类型：**读取原特效类型
- **特效名称：**同一单元格分行显示全部已配置语言，标注语言；当前原型为简体、繁体、英文、阿拉伯语、土耳其语、西班牙语
- **缩略图：**只展示一张，不再按语言拆列，复用现有后台资源展示规则
- **金币单价／天：**正整数日单价
- **可购买时长：**展示已勾选的时长，按 3、7、15、30 天升序排列
- **排序：**整数，默认 0，排序值越大越靠前
- **状态：**无文字开关，开为上架、关为下架
- **创建时间：**商城配置创建时间
- **修改时间：**商城配置最近修改时间
- **操作：**编辑、删除

列表支持分页，无记录显示空态；查询、重置回到第一页。按本次最新字段顺序展示，不沿用旧版将排序放首列、状态紧贴操作列的排列。

### 2. 批量创建／单条编辑

新增弹窗标题「新增」，默认一行，可添加、删除行，每行代表一条商品配置；编辑弹窗标题「编辑」，一次编辑一条记录。

- **特效类型：**创建规则：必选，复用线上下拉；编辑规则：回显、只读
- **特效 ID：**创建规则：按类型选择，显示「名称（ID）」，复用线上分页下拉；编辑规则：回显名称及 ID，只读
- **名称、缩略图：**编辑弹窗不显示额外的名称及缩略图预览区域；商品关联信息仍从特效列表读取
- **金币单价／天：**创建规则：必填，正整数；编辑规则：可修改
- **可购买时长：**创建规则：3、7、15、30 天多选，至少一项；编辑规则：可修改，至少保留一项
- **排序：**新增时手动输入整数，默认 0，排序值越大越靠前，不自动递增；编辑时支持修改
- **状态：**创建规则：上架／下架单选，默认下架；编辑规则：选中当前值，可修改

- 未选择特效时不显示“选择特效后回显名称、缩略图”占位提示；“删除此行”使用带边框的按钮样式。
- 特效 ID 选项读取所选类型下已在特效列表创建的特效，不从商城列表生成；未选择类型前不可选择 ID。
- 同一特效只允许存在一条未删除的商城配置，下架也不可重复创建；同批次内也不允许重复。删除商城配置后允许重新创建。
- 每行独立选择类型、资源及销售参数；切换类型只清空该行已选特效及名称、缩略图回显，不清空其他行。无可选特效显示空态。
- 至少有一行才能提交。点击「确定」统一校验全部行；任一行错误，在对应字段下提示，保留所有输入，本批次不部分保存。
- 上架行必须校验对应特效已启用；下架状态保存不受启用状态限制。
- 全部校验通过后统一保存，成功刷新列表；保存失败保留输入，取消不保存。编辑同样遵循字段校验。
- 按实际错误在对应字段下方提示，修正后清除，预留提示空间，不挤动或遮挡控件。排序 0 有效，编辑时不得重置未保存内容。

### 3. 上下架与删除

- 关联特效须先在特效列表启用才允许上架商城；未启用时提示「请先在特效列表中启用该特效」。列表开关上架、创建／编辑以上架状态保存均校验，下架保存不受此限制。
- 上架商品按现有缓存刷新机制展示并可购买。下架、删除后提交购买需拦截，客户端缓存更新后移除商品；该类型无剩余可售商品时同时隐藏分类。
- 删除需二次确认：「确认删除该商城商品？」；按钮为「取消」「确定」。仅删除商城配置，不删除原特效资源，删除后可重新创建。
- 改价、修改时长、上下架、删除均不影响已购权益、当前佩戴及历史购买记录。

### 4. 购买记录

菜单：商城管理 → 购买记录，仅展示成功订单，不提供编辑、删除操作。

- **用户 ID：**精确查询
- **特效 ID：**精确查询
- **特效类型：**默认全部，复用类型枚举
- **购买时间：**起止日期，包含起止日期全天；开始日期不可晚于结束日期，未选择则不限

支持组合查询、重置，字段名称与组件横向排列；顶部只展示「订单总数」「订单总金额（金币）」，与全部筛选条件联动，统计全部匹配记录而非当前分页，无数据时显示 0。

列表字段依次为：订单号、用户 ID、特效 ID、特效名称、特效类型、成交金币单价／天、购买有效期（天）、消耗金币数量、购买时间。特效名称仅英文，用户字段按本次最新稿显示 ID；不展示订单状态、到账时间、失败原因。

页面不展示“演示数据 · 仅成功订单 · 总览统计全部筛选结果”说明。按购买成功时间倒序排列，支持分页。展示购买时信息，后续修改、删除或重建商品均不覆盖历史订单信息。消耗金币数量为本笔实际成交金额。

## 三、服务端

### 1. 商品展示与购买处理

- 返回已上架可售商品信息、关联特效资源、每日单价、可购买时长和排序；客户端分类按实际可售类型动态返回，不保留空分类。类型按本稿客户端范围及相对顺序展示。
- 商品名称、缩略图、多语言及预览复用现有特效数据；商品配置展示复用礼物面板缓存及刷新机制，不要求实时同步。
- 提交时校验商品可售、时长允许、余额足够，总价由服务端计算，不信任客户端金额。
- 成功后扣币、增加对应特效有效期，生成金币消费及商城购买记录，各结果保持一致。
- 购买装扮消耗的 Coins 计入财富经验、消费任务、消费榜单等，按现有消费统计规则执行。
- 同一笔交易只处理一次，重试不得重复扣币或发放，并发不得超扣；超时核实原交易结果。
- 每笔成功订单保存用户、商品／特效、购买时英文名称和类型、成交日单价、购买天数、实际消耗金币、购买成功时间。后台成功记录与筛选汇总使用同一口径。
- 后台保存时校验单价、时长、整数排序、关联特效、重复配置及上架启用状态；批量新增整体校验，全部通过后统一保存。

### 2. 有效期与来源

- 同一特效 ID 跨商城、活动、经理发放等渠道统一累计；1 天＝24 小时。
- 未拥有或已过期，从本次发放成功时间计算；未过期，在原到期时间上增加购买时长。
- 商城购买成功后，仅增加对应特效的有效期，不自动佩戴，不改变用户当前佩戴状态。到期及佩戴处理沿用现有能力。
- 本次来源记录为「商城购买」，不覆盖其他历史来源。

## 四、原型说明与验收重点

H5 用于产品交互演示，使用模拟特效、缩略图、余额、充值及订单；数据保存在当前浏览器，同浏览器商城操作与后台配置、购买记录可联动。特效播放使用一次性模拟动画；正式版本复用真实特效、线上充值、装扮页及分页下拉。原型沿用新稿的字段与菜单，旧版示例数据不作为真实成交数据迁移。

重点验收：动态分类及全空态、排序降序、预览不改变选择且只播放一次、抽屉默认档位及充值返回保留档位、日单价乘天数、成功弹窗与装扮分类跳转、批量保存不部分成功、特效重复与启用校验、排序 0 有效且不自增、日期筛选包含全天、汇总不受分页影响、购买不自动佩戴、历史成交信息不随商品变动。

配置变更的具体错误提示复用现有机制；原型在提交时发现日单价变化，会先更新抽屉并要求用户再次点击购买，避免按用户未看到的新金额直接扣费。正式实现仍需与线上礼物面板相同场景的处理保持一致。
